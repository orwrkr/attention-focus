# ADR-0036: One EXE as the Release

Date: 2026-11-05.
Status: accepted.
Basis: explicit user request to ship a single EXE, with licenses embedded as far as is sufficient,
and to leave an installer for later.

## Context

A release was a ZIP with the EXE, a PDF guide, a notices file and a manifest, although only the EXE
is needed to run. The question was whether a bare EXE is allowed, because a third-party license text
has to reach whoever receives a copy.

The EXE contains 137 third-party packages, and all are under permissive licenses: MIT, Apache-2.0,
BSD, Zlib, ISC, BSL-1.0, Unlicense, Unicode-3.0, OFL-1.1 and the Ubuntu Font Licence. One package
offers `Apache-2.0 OR GPL-2.0-only`, and Apache applies. None of them asks for an installer or a
separate file. OFL and the Ubuntu licence allow the text in metadata within binary files "as long as
those fields can be easily viewed by the user", and Apache-2.0 allows notices "within a display
generated by" the program. So the text must be inside the copy and readable by its user. This is the
project's reading of the licenses, not legal advice.

## Decision

**The EXE carries the notices.** Settings has an About part with the application's license and a
**Licenses** button that shows the whole text. `build.rs` compresses it with `miniz_oxide`, which
the dependency tree already had through `png`, so this adds no package. It adds about 105 KB rather
than 2.9 MB. The text is inflated only when opened and dropped when closed, and only visible rows are
laid out, since it has about 55,000 lines. Rows wrap to the width of the window, so the view needs no
horizontal scroll bar, which egui would otherwise lay over the text when the window cuts the area off.

**The notices are a tracked, generated file**, `third-party/THIRD-PARTY-NOTICES.txt`. Generating at
compile time would make every debug build and test need Python and the complete package registry.
`scripts/build.ps1` regenerates it before compiling, and both workflows fail when it is out of date,
so a change of dependency or toolchain shows up as a reviewable change of license text. It holds no
version number, which would change it on every bump.

**A release is a folder of three files.** `dist/AttentionFocus-VERSION/` holds exactly
`attention-focus.exe`, `User-Guide-VERSION.pdf` and `release.json`, and a GitHub release attaches
those three. The EXE keeps its stable name, so replacing it keeps sign-in startup and shortcuts. The
guards stay as ADR-0011 set them: a build stamp, an exact allowlist, hashes, and a version bump once
inputs change for a released version. The folder is built aside and swapped in, and a failure
keeps the previous one. Older folders and ZIPs in `dist/` remain release history.

Signing is unchanged, as the workflow already submitted only the EXE. A signature now also covers the
license text.

## Alternatives

- An installer: the owner deferred it, and the licenses do not require one.
- Keeping the ZIP: an extra step for the user, for files they do not need to run the program.
- A notices file only on the release page: it would not travel with a copy of the EXE.
- Embedding the text uncompressed: 2.9 MB more in every copy.
- Tracking a compressed file: its changes could not be reviewed.
- Opening the text in another program: it would mean writing a file and depending on that program.
- Horizontal scrolling instead of wrapping: most lines would need it at the usual window width.

## Consequences

The download is the EXE alone, about 12.6 MB, where the ZIP was about 5.4 MB. The repository gains
a 2.9 MB text file that changes with dependencies. A copy of the EXE has no manifest beside it, so
hashes are checked against the release that published it. Changing dependencies now needs one more
committed file, which CI enforces.
