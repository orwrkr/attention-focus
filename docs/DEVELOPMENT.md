# Development and Deployment

## Requirements

- Windows x64 with the Rust MSVC toolchain (verified toolchain: Rust/Cargo 1.98.0).
- MSVC C++ build tools and Windows SDK for native linking and bundled SQLite.
- Access to crates.io for the first dependency download.

The application uses eframe 0.37.0, tray-icon 0.26.1, rusqlite 0.41.0,
and winresource 0.1.34. Cargo.lock records the resolved dependency graph.
Build from the repository root so .cargo/config.toml enables the static C runtime.
Icons are generated by build.rs and embedded in the Windows executable resources.

## Commands

```powershell
cargo fetch --locked --target x86_64-pc-windows-msvc
cargo fmt --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked --release
cargo run --locked
```

The release executable is `target/release/attention-focus.exe`.
The distributable copy is `dist/AttentionFocus/attention-focus.exe`; that folder
contains only the executable. The final PE import audit found only Windows system
libraries and no separately shipped runtime or SQLite DLL (see T-0006).
Build output is ignored by Git. No installer, automatic startup, or updater is added.
Runtime requirements on a clean Windows machine have not yet been verified; do not
describe this build as universally portable.

## Runtime files and data

No asset files are required beside the EXE. Fonts, window/tray icons, shell icon,
and version metadata are embedded. SQLite and the MSVC runtime are statically linked
by the Windows target configuration. The PDB is optional debugging information.
Windows system libraries and a working graphics driver are still required. No Rust,
Node, WebView2, or .NET runtime installation is needed for this native build.

The Windows LocalAppData known folder supplies the fixed application data location:

- `%LOCALAPPDATA%/AttentionFocus/window.ron`: position, size, and maximization.
- `%LOCALAPPDATA%/AttentionFocus/focus.sqlite3`: unassigned sessions and checkpoints.
- SQLite may create temporary journal files in that same directory.

Moving the EXE does not reset history. Back up the data directory after exiting.
Source configuration is not implemented; future source selection must reject overlap
with this storage root. Nothing is stored beside the EXE or in MetaPlan.

## Current behavior

- Startup restores window geometry and opens a visible English window with a tray icon.
- A worker owns durable SQLite history. Sessions currently belong to Unassigned focus.
- Start/Stop in the window and tray use the same controller; the tray state changes
  only after the session update commits.
- Closing the window or using Hide to tray keeps the process running.
- A single left click shows the window after the Windows double-click interval.
- A native double left click toggles tracking once and cancels single-click opening.
- Hover shows a native tooltip with session time and total saved plus active time.
  It updates once per second while running, including when the window is hidden.
  Unreviewed interrupted time is excluded and flagged. Windows controls tooltip delay.
- Right click opens Show Focus, Start/Stop, and Exit.
- The app logo has a green focus ring and center dot. Running uses a green play
  symbol; stopped uses gray pause bars, distinguishing states by shape and color.
- Exit saves the running session before terminating. Restart never resumes silently.
- Checkpoints are saved every ten seconds. Interrupted records require review before
  starting again; accepting recovery keeps only the last checkpoint and excludes downtime.
- A detected scheduling gap over 30 seconds or a wall-clock divergence over five seconds
  interrupts tracking. OS lock/suspend notifications remain T-0004 work; short sleeps
  are not yet fully handled by this bootstrap timer.
- A per-profile mutex rejects a second instance in the same Windows session.
- Tray setup failure leaves the window usable, disables hiding, and lets window
  close exit. The UI displays the failure instead of hiding silently.
- Tray callbacks wake the event loop. Stopped tracking has no periodic timer updates;
  running tracking updates once per second. Geometry autosaves after movement and on exit.
- MetaPlan is not read or modified. Project selection and date-range reports remain
  future work; the UI currently shows elapsed time and accumulated saved totals.

## Manual verification checklist

1. Move/resize the window, wait three seconds, hide it, and exit through the tray.
2. Relaunch; verify geometry restoration, including maximized/multi-monitor cases.
3. Check the EXE, taskbar, Alt-Tab, Task Manager, and both tray state icons.
4. Double-click the tray to start, then stop. Verify one change per double click and
   no unwanted window opening on surrounding single-click events.
5. Use Show Focus and Exit both visible and hidden; restart and check saved totals.
6. Verify interrupted recovery using disposable test history, never real history.
7. Check tray failure, unwritable storage, and a clean Windows machine.

This is an initial unassigned timer, not the completed project-aware focus tracker.
